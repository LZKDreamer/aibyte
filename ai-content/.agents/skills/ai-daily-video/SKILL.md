# AI 日报视频

仅在用户明确调用 `$ai-daily-video` 时使用。本 Skill 与 `ai-daily` 完全独立：它只消费一篇已经存在的 Markdown，绝不抓取、改写或发布日报文章。

## 输入与输出

输入为一个 `.md` 文件，成片的唯一时间轴来自确认后的 `captions.srt` / 词级时间戳。可选素材以 Markdown 图片、同目录的 `materials.json`、`assets/materials.md` 和 `assets/videos/` 提供。默认先使用本地素材；用户要求“搜集素材”“录制页面”或明确要求按字幕补画面时，必须进入联网素材流程：按字幕语义搜集公开官方页面、公告、产品页和公开演示，并优先用 Playwright 录制真实动态画面。每条字幕内容必须保留；没有合适的真实视频时，依次使用可信动态视频、桌面录屏或有连续运动的原创动态图解，不能删掉、合并或替换该条内容。不得用静态信息卡、PPT、幻灯片或长时间停留的图片替代视频，除非用户明确允许。详细设计合同见 [references/design-system.md](references/design-system.md)。

默认输出目录是 `ai-daily-output/ai-daily-bundle/output/YYYY-MM-DD/01/video/`。输入日报位于同一日期的 `01/article/article.md`；视频输出目录与文章目录同级：

```text
script.md                 # 待审核口播稿
storyboard.json            # 待审核分镜、素材映射和时长
materials-report.json      # 每条新闻最终采用或缺失的素材
materials-search-plan.json # 字幕语义段到素材需求的映射
assets/recordings/          # Playwright 浏览器录制的原始 WebM
assets/context/             # 语义相关的动态视频，不冒充官方证据
assets/screenshots/         # 页面截图和公告截图，仅作内部核验
assets/videos/              # 剪辑后的成片视频素材
frame.md                   # 本期套用默认视觉系统后的设计锁定稿
voiceover.mp3              # 审核后生成
word-timestamps.json       # 审核后生成，词级时间戳
captions.srt / captions.ass
hyperframes/index.html
final.mp4
verification.json
```

## 目录与依赖

- `ai-daily-output/ai-daily-bundle/output/YYYY-MM-DD/01/article/`：`ai-daily` 生成的日报输入目录。
- `ai-daily-output/ai-daily-bundle/output/YYYY-MM-DD/01/video/`：本 Skill 生成的审核包、字幕、HyperFrames 项目和成片。
- `ai-daily-output/ai-daily-bundle/dependency/ai-daily-video-runtime/`：HyperFrames、GSAP 等视频运行时依赖；渲染时只能在这里安装或复用。
- `ai-daily-output/ai-daily-bundle/dependency/ai-daily-pipeline/node_modules/playwright/`：公开页面的生产录制优先复用 Playwright；录制尺寸固定为 1080×1920。`browser-harness` 只用于用户明确要求复用已有浏览器状态的交互，不作为生产录制器。
- `ai-daily-output/ai-daily-bundle/dependency/Agent-Reach/`：需要用户明确要求联网取素材时，读取公开网页、RSS、YouTube 字幕和平台数据。
- `.agents/skills/ai-daily-video/scripts/`：本 Skill 的处理脚本，不属于日期输出文件。

如果用户明确要求本 Skill 联网搜集或补充素材，执行处理前先运行共享预检：

```powershell
node .\.agents\skills\ai-daily\scripts\ensure-web-dependency.mjs agent-reach --json
```

应按能力只调用一个依赖：公开内容使用 `ensure-web-dependency.mjs agent-reach`，已有 Chrome 登录态和交互使用 `ensure-web-dependency.mjs browser-harness`；命令返回的 `skillPath` 是本次应读取的本地第三方说明。缺失时依赖只安装到 `ai-daily-output/ai-daily-bundle/dependency`，不写全局 skill 目录，不自动处理 Cookie、代理或登录。公开页面生产录制不得依赖登录态、验证码或访问限制；不绕过限制，不录入个人信息。

## 阶段一：生成审核包（默认）

运行：

```powershell
node <SKILL_DIR>/scripts/prepare.mjs "<article.md>"
```

它生成约 3–4 分钟的草案：简短开场、逐条新闻、轻量结尾。口播要采用参考片的节奏：短句、先说这条新闻发生了什么，再补关键事实；稿件必须以文章事实为准，口语化重写而不是逐字朗读，也不能照抄参考视频的原句。

### 口播稿事实边界与模板

日报中的每个二级标题都是一条独立新闻。默认按原文顺序逐条播报，**不要求、也不得为了流畅而人为建立它们之间的因果、趋势、对比或共同主题**。

- 只陈述文章标题和正文明确支持的事实；保留原文的时间、范围、数字、用户群体和不确定性限定。
- 禁止把多条新闻概括为“价格在变”“行业都在……”“这说明……”等总趋势，除非文章本身明确作出了该总结，并能标明对应段落。
- 禁止用“更关键的是”“因此”“也意味着”“说明了”等词引入文章未明说的判断；“此外”“下一条”“最后一条”仅可用于顺序衔接。
- 一条新闻只讲自己的变化和必要事实。没有可靠关联时，保持独立呈现，不补过渡逻辑，也不因此删除或替换该条内容。
- 保留不确定性：原文出现“尚未确认”“仍有不同说法”“未公布”等内容时，口播必须保留，不得弱化为既定事实。
- 开场只可说明“今天有 N 条更新”或直接进入第一条；不要预先归纳全部新闻。默认在最后一条新闻结束，不生成“收束”画面、总结口播或互动邀请；只有用户明确要求时才添加结尾。

### 参考口播节奏

参考片的已转录文本位于用户提供的参考素材目录中。可借鉴其“变化在前、事实在后”的短句节奏，但不能迁移其中未被当前文章支持的夸张、评价或行业判断。

- 开场用一句短钩子报出条数，随后直接进入第一条；不在开场罗列全片的抽象主题。
- 每条采用“主体 + 明确变化 → 1–2 句关键事实”的推进方式。正文中的具体能力、数字、用户范围或已知限制优先于泛泛形容词。
- 用“先看”“再看”“还有”“最后”做纯顺序提示即可；这些词不表示新闻之间存在关联。
- 可在文章明确描述产品能力时，用短句拆开呈现；不将“突破”“压制”“正式进入”等强判断当作默认措辞。
- 单条默认 2–3 句，信息足够时即停，不用为了模仿节奏补案例、反应或结论。
- 二级标题只用于审核、分镜和字幕索引，不默认朗读。口播直接从正文中说明变化的首个完整句子开始，避免“朗读标题后再重复正文”。

口播稿是可直接念出的连续文案，不是文章提纲。`script.md` 中不得出现 `01`、`02`、`hook`、`outro` 等编号或制作标签；新闻序号只保留在 `storyboard.json` 中供制作使用。

按以下模板生成，每一段均可独立成立：

```markdown
今天有 N 条 AI 更新，先看第一条。


[将第一条的变化改写成 1 句可说出口的话]。[用 1–2 句补充必要事实；保留数字、范围和限定]。


[将下一条的变化改写成 1 句可说出口的话]。[用 1–2 句补充必要事实；保留数字、范围和限定]。

```

改写必须改变书面句式，而不能只删掉标题后照读正文。优先拆开长定语和并列成分，用短句承载同一事实；例如把“功能已正式推出，覆盖所有付费用户”改成“这个功能已经上线了。付费用户现在都能用。”不得新增未被原文支持的对象、原因或评价。

检查 `script.md` 和 `storyboard.json` 后，向用户展示：预计总时长、每条新闻的素材来源与所有无素材条目。此阶段不得调用 TTS 或渲染。

`prepare.mjs` 只负责提取文章事实、创建分镜与给出初稿。向用户交付前，必须依照本 Skill 的口播规则逐段重写 `script.md`，并把相同旁白、时长与起止时间同步回写到 `storyboard.json`；不得把机器抽取的正文句子直接当作最终口播稿。

## 阶段一半：按字幕搜集和录制视频素材

当用户要求“搜集素材”“录制页面”或“按字幕补画面”时，先完成本阶段，再进入确认和渲染。`captions.srt` 是唯一时间轴；不能先套模板再临时找画面。

1. 读取 SRT，按语义而不是按固定字数拆成画面段，生成 `materials-search-plan.json`。每段必须包含字幕起止时间、新闻主体、需要证明的数字/范围/状态、优先来源和备用画面。
2. 按以下顺序找素材：官方产品页或公告 → 官方公开演示 → 可信公开动态视频 → 自制连续运动视频。官方页面只用于支持它明确展示的事实；语义相关视频只能记为 `context`，不能写成官方证据。
3. 页面生产录制使用 Playwright，不使用 browser-harness 代替。录制前设为 1080×1920，等待正文可见、字体和图片稳定后再开始；清除加载指示器，关闭平滑滚动、CSS 动画和过渡。优先录制真实操作、页面滚动、展开、搜索或播放动作，每段保留约 3–8 秒关键动作。
4. 滚动必须作用于实际可滚动容器（`document.scrollingElement`、`body`、`main` 或页面中最大的滚动容器），不能只调用 `window.scrollTo`。每次滚动后等待页面稳定，避免懒加载文字闪烁；开始录制前后都检查首帧和关键帧，不得出现白屏、灰屏、加载占位或未渲染页面。
5. 原始录制先剪掉启动等待，再统一转为 30fps、H.264、GOP 不大于 30 的 MP4。每个视频源的有效时长必须覆盖它对应的字幕段；禁止把短视频循环播放、重复同一小段、播放结束后停留最后一帧或用静帧填满剩余时间。覆盖不足就换素材、补录另一个动作或改用另一段真实动态视频。
6. 无法获得直接证据时，使用 `context` 或 `original` 类型的动态画面；`original` 必须有可见连续运动。不得在画面中添加“示意画面”或类似免责声明，也不得伪造官方界面、新闻现场、产品交互或来源截图。
7. 内部 `materials-report.json` 记录来源 URL、录制时间、素材类型（`evidence`、`context`、`original`、`screen-record`）、用途、有效时长、首帧检查和验证状态。相似视频必须明确标为 `context`；不把它写成官方证据。

完成后逐段检查：每个字幕段都有真实动态画面；画面不是信息卡、幻灯片或静态长图；页面文字不闪烁；素材不会白屏启动、提前结束或停在最后一帧。检查未通过时不得进入渲染。

## 阶段二：经确认后生成成片

用户明确确认脚本与分镜后，运行：

```powershell
node <SKILL_DIR>/scripts/render.mjs "<article.md>" --approved
```

渲染流程固定如下：

1. 调用 `${AI_DAILY_VIDEO_TTS_URL:-https://tts.wangwangit.com/v1/audio/speech}`，发送 `zh-CN-XiaomengNeural`、`speed: 1.15`、`pitch: "25"`、`style: "newscast"`。
2. 使用 `AI_DAILY_VIDEO_PYTHON` 指定的 Python（未指定时自动识别 `py`、`python` 或 `python3`），并用 `AI_DAILY_VIDEO_WHISPER_MODEL` 指定 faster-whisper 模型目录，以 `device=cpu`、`compute_type=int8` 生成词级时间戳。模型或 Python 不存在时立刻报出缺失项；不要降级模型。
3. **转录比对与校正（强制）**：将 faster-whisper 的每个转录片段与确认后的 `script.md` 逐句规范化比对，并输出 `transcription-comparison.json`。`script.md` 是唯一的字幕文案来源；faster-whisper 只用于时间戳。转录中的专有名词、英文单词、数字或中文误听，必须以 `script.md` 的原文替换，不能直接进入 SRT、ASS、JSON 字幕或画面。若片段数量或顺序无法可靠对齐到口播稿，停止渲染并报告需人工复核的片段；不得猜测或静默降级。
4. 基于**校正后的口播稿文本**和词级时间戳生成 SRT、ASS 与 `captions.json`。字幕按完整句子或完整意群切分，优先在句号、逗号、分号等自然停顿处断开；不得按固定字符数硬切，不得将英文单词、数字、产品名或专有名词拆成两段。一个句子拆为多个意群时，必须按对应词级时间戳确定每个意群的起止时间，禁止把整句时长平均分配给各段；后一段字幕只能在其首个词实际开始时出现。每屏最多两行，字幕位于底部安全区上方；逐词高亮时仅高亮当前词。
5. 读取 [references/design-system.md](references/design-system.md)，在本期 `frame.md` 和 `storyboard.json` 记录模板组合，例如 `play-mode + product-promo + decision-tree`。默认使用 `visualMode: "media-first"`：视频、动态图片层和原创动态图解可以混合，但媒体必须占据主画面并持续运动。只有用户明确要求“全是真实视频”时才使用 `visualMode: "video-only"`，并由构建脚本拒绝非视频场景。字幕是唯一允许的常驻大段文字层；不叠加大标题卡、关键事实卡、PPT、幻灯片或静态长图。
6. 在 `ai-daily-output/ai-daily-bundle/dependency/ai-daily-video-runtime/` 安装或复用 HyperFrames 运行时，执行 `check`、快照与渲染。仅在检查通过后产生 `final.mp4`。
7. 运行成片校验，确认尺寸、时长、非空文件、抽帧非黑/非白/非灰占满、各字幕段均有动态媒体或原创动态图解、视频首帧已渲染、没有短视频循环或最后帧停留、字幕安全区，以及 `captions.json` 与确认 `script.md` 的文本一致性。最终视频时长以字幕最后结束时间为准，不能保留 HyperFrames 的多余尾帧；失败时保留中间文件并给出重试命令。

## 视觉边界

- 参考视频只用于拆解节奏、信息层级和“素材主导”的做法；不得复制其频道名称、Logo、固定标题、口播文字或画面资产。
- HyperFrames 官方示例只用于选择结构和动画语法。默认优先参考 `play-mode`、`product-promo`、`swiss-grid`、`decision-tree` 和 `nyt-graph`，按本期字幕组合改造；不把任何模板原样当作固定成片。
- 不使用背景音乐，除非用户另行提供可用音频素材。
- 素材只显示在对应新闻段。`materials.json` 中标记的 `videoAsset` 优先于图片；用户要求视频时，素材不存在、不可读或不匹配就继续搜集、录制或替换为动态 `context` / `original`，不能静默改成信息卡。
- 默认仅输出审核包；`--approved` 是唯一允许发送 TTS 请求或渲染的开关。

## 默认视频视觉系统

以下是所有 AI 日报视频的默认设计规范，也是 HyperFrames 渲染的唯一默认来源。具体模板选择、媒体等级、动态图解边界和无素材处理以 [references/design-system.md](references/design-system.md) 为准；每期输出目录中的 `frame.md` 只能记录该期的模板组合、素材映射、文案长度导致的字号调整和经用户确认的例外；它不能重新定义品牌、颜色、组件或基础布局。

### 设计概念

使用 **AI Product Reel**：以 HyperFrames `play-mode` 的节奏组织真实录屏、公开演示、动态图片层和原创动态图解。画面像正在运行的 AI 产品系统，冷黑底、冰蓝信号线、少量橙色状态提示；媒体动作优先，单个镜头只强调一个事实。`product-promo` 负责真实产品动作，`swiss-grid`、`decision-tree` 和 `nyt-graph` 负责将价格、权限、趋势和不确定性做成连续运动；任何模板都不能退化成 PPT 面板。完整令牌和组件规则见 [references/design-system.md](references/design-system.md)。

### 稳定模板锁定：AI Product Reel v1

以后默认沿用本版本，不因单期素材变化改成新的卡片风格或新的窗口结构：

- 画布固定为 `1080×1920 / 30fps`，模板字段固定为 `visualTemplate: "ai-product-reel"`，默认 `visualMode: "media-first"`。
- 画面固定为“黑色 AI 网格背景 → 顶部 AIBYTE 栏 → 中央产品窗口 → 窗口下方动态图解 → 底部字幕”。字幕是唯一允许持续存在的大段文字。
- 场景切换默认硬切。不得只给 `.evidence`、`.fact`、`.masthead` 或边框组件添加进入/离开位移动画；若确实需要转场，必须把媒体、边框和动态图解放进同一个共享根节点后整体移动。
- 产品视频必须裁切在圆角产品窗口内；窗口使用 `overflow: hidden`，视频使用不变形的 `object-fit: cover` 和 `center top`，不能让视频底部两个角超出边框。
- 顶部栏字号约 `24px`，动态图解主说明约 `40px`，动态图解标签约 `18px`，字幕距底部约 `112px`。这些是默认基线，只有为适配文案长度才允许局部缩小。
- 内部素材验证信息只写入 `materials-report.json`，不得出现在画面上；尤其不得渲染“示意画面”“官方声明关联待确认”“关联待确认”等制作备注。文章原文中的不确定事实仍须保留在口播和字幕中。

构建脚本和 `verify.mjs` 会检查这些不可漂移的结构标记；检查失败时停止渲染，而不是自动退回旧版信息卡。

- 关键事实 76–96px；大数字 96–144px；动态图解说明 34–40px；制作索引 18–24px；字幕约 36–40px、700。
- 稳定模板使用左右 54px；顶部栏约 56px；产品窗口从 y=208px 开始，高约 1050px、圆角约 30px；窗口下方动态图解卡从 y=1290px 开始，高约 365px、圆角约 26px；字幕默认 `bottom: 112px`。
- 主信号色只用于光标路径、节点、数据线和当前变化；橙色只用于价格/状态变化；珊瑚色仅用于文章原文明确存在的限定，不得把内部证据核验状态写成画面标签。不得为每条新闻另起主色，不用渐变文字或满屏线性渐变。

### 固定画面架构

1. **顶部 72–180px**：`AIBYTE / AI TECH UPDATE`、当前序号和产品短标签。只作识别，不做新闻标题卡。
2. **中段 180–1,620px**：统一 AI 产品窗口。中央媒体窗口展示真实产品动作；窗口下方使用连续运动的动态图解解释一个价格、权限、路径或状态变化。
3. **前景层**：短暂出现的信号线、光标路径、节点和状态标记；它们必须服务于画面动作。
4. **底部 1,620–1,820px**：字幕安全区。字幕不能遮挡产品操作或生成结果。

视频场景使用中央产品窗口播放真实或公开动态素材，保留轻量顶部产品标记、窗口顶栏、窗口下方动态图解和底部字幕；不使用旧版证据窗口、关键事实卡或固定 footer。字幕不能替代视频，也不能在视频结束后继续显示最后一帧。场景之间的边框、媒体和动态图解必须保持同一坐标系，禁止出现“图片不动、边框在动”的错位。

不使用暖灰纸面、LOCAL EVIDENCE 索引轨或旧版米灰证据卡。可以使用统一的浅色产品窗口顶栏和三色控制点作为构图容器，但不能伪装成来源网页。产品素材放在窗口内，顶部只保留短栏目名、序号和产品标签，底部保留字幕。

每一画面至少保留两个焦点：产品动作/结果和信号路径/状态变化。标题和事实优先左对齐或贴边锚定，不使用全片居中堆叠。背景使用低对比节点、轨迹、局部冰蓝亮斑和细线漂移提供 AI 系统感，但不能压过素材。

### 素材与信息视觉

- 素材只出现于它对应的新闻段。`videoAsset` 优先于图片；视频画面可轻推近或滚动，但不能循环短片、停在最后帧或用静帧补时长。
- 有素材时，视频先进入并持续运动；除字幕外不要把大标题、关键事实卡或大段说明文字压在素材主体上。
- 图片可以作为原创动态图解的动画图层，必须有平移、缩放、遮罩、视差、重组或其他可见状态变化；不能作为字幕段的静态背景。无素材必须继续搜集动态素材、录制桌面或制作有连续运动的原创视频，不能删除该条内容。原创视频不能伪造产品截图、模型界面、评测图或来源引用。
- “尚未确认”“规则未公布”等文章事实必须在口播和字幕中保留，不能被渲染成已经完成的产品流程；但“官方声明关联待确认”等内部核验备注只留在内部报告，不作为画面文案。

### 字幕与节奏

- 字幕最多两行，每行最多 12 个汉字或两个短词组；使用浅色文字、轻薄深色半透明底或文字阴影，不使用大面积灰色圆角气泡。
- 若启用逐词高亮，信号色只跟随当前词，不能同时高亮整句和关键事实。
- 节奏固定为：短钩子 → 证据停留 → 信息快切 → 证据停留 → 限定提示 → 安静收束。
- 媒体动作使用“锁定、展开、轻推近、跟随光标”；文本使用“擦入、对齐、锁定”。默认场景硬切，不给父级边框单独加转场；只有共享根节点能保证媒体和边框同步时，才允许 0.2–0.4 秒的方向性推切、网格擦除或轻微缩放交接。禁止无意义的故障、火焰、旋涡等转场。

### 渲染验收

- 不含参考视频的 Logo、频道名、栏目固定条、浏览器窗框或素材；不添加“示意画面”“官方声明关联待确认”或其他内部制作备注。
- 所有场景都不是 PPT、幻灯片或静态信息卡；不得出现白屏、灰屏、加载占位、首帧空白、短片循环或播放结束停帧。没有真实素材时，必须用连续运动的原创动态图解覆盖字幕时间轴。
- 静音观看时，每条新闻仍能识别“主体 + 变化 + 一个关键事实”。
- 每屏只突出一个数字、一个状态或一句关键事实。
- 没有素材的条目不伪造证据；所有素材映射在 `materials-report.json` 可追溯。
- 字幕在安全区内，且与确认后的 `script.md` 完全一致。
- `frame.md` 不得覆盖本节令牌和规则；如用户确认例外，必须逐条记录例外及原因。

## 故障处理

- TTS 请求失败：停止，不切换声音；提示配置 `AI_DAILY_VIDEO_TTS_URL` 指向自建兼容服务后重试。
- faster-whisper 失败：停止并保留 `voiceover.mp3`；不使用 GPU/CUDA，也不降级为非词级字幕。
- HyperFrames 检查或渲染失败：保留 composition 和快照，报告原始错误与重试命令。
