# AI 日报

仅在用户明确调用 `$ai-daily` 时使用。日报的主选题池固定为 `https://xbangdan.com/lanes/` 的 **24小时 / 综合热度 / AI**。这不是官网新闻汇总；榜单摘要与其对应 X 原帖才是核心内容。

X 榜单是选题、排序、文案密度和素材的**主标准**。主帖与榜单关联信源只用于补全、核对榜单卡片已有事件的具体事实和媒体；绝不用于替换榜单选题、重新排序或淘汰没有官网公告的热点，也不得自行扩展到官网、搜索引擎或其他外部来源重搜。AI 长文使用 `/articles/`，不属于本 Skill。

## 固定流程

1. 在 `D:\codeproject\aibyte\research-pipeline` 运行：

   ```powershell
   node capture-xbangdan.mjs
   node build-candidates.mjs
   node select-daily.mjs
   node build-daily-cover.mjs
   ```

   读取 `output/daily-shortlist.json`，确认 `observedFilters` 包含 `24小时`、`综合热度`、`AI`。它按榜单页面顺序给出前 12 条，不混入其他来源的候选。

2. 用 Playwright 完整读取榜单中每个入选条目的**事件组**，而不只读取候选文件中的短摘要。逐条记录和理解：`headline`、`summary`、主帖详情 `ltr-x`、展开的关联信源 `lev-m`、`related`、作者/时间/阅读/互动/热度等 `meta`，以及新闻媒体 `thumb`。X 榜单已完成信息收集、聚合与排序；日报必须以这些内容为主。

3. 按榜单顺序选择 8–12 条写入日报。第一条必须是榜单第一名；其余条目原则上保留榜单顺序。相似事件可以合并，但不能为了强行分类而删掉热点。

4. 用 Playwright 打开每条的主帖，必要时打开榜单列出的关联信源，补全或核对事件组里的具体事实、可用范围、机制、原话和对应媒体。原帖不是重新选题或另写报道的依据，也不得逐句搬运。**遇到登录墙、访问受限、加载失败或浏览器会话不可用时，先明确提示用户并暂停，等待用户决定继续登录、改用榜单内容或跳过该条；不得自行扩展到官网、搜索引擎或交叉验证。** 用户决定采用榜单内容后，直接继续写，不为长篇溯源拖慢日报。

5. 先检查每个事件组的 `thumb`，再决定配图，不得只核验第一条。普通 X 图片直接作为该条候选图；视频条目使用榜单提供的视频封面/缩略图作为日报配图，并尝试从**同一条 X 原帖**获取原视频的最高可用 MP4，保存到当天 `assets/videos/`、在 `materials.json` 与 `assets/materials.md` 登记。若原帖只提供不可稳定下载的分段流，要如实记录原因；不能把“只保存封面”写成已下载视频。日报网页仍使用视频封面，不嵌入播放器。头像不是新闻配图，不能采用。每张图都要人工判断：与该条内容直接相关、主体清楚、文字可辨且无大面积空白时才采用；没有 `thumb` 或无合格图时保持纯文字。图片和视频封面不能独立证明事实，登记为 `illustration`。

6. 在 `ai-content` 创建当天输出目录：

   ```powershell
   node .\scripts\create-daily-output.mjs YYYY-MM-DD
   ```

7. 正文完成后，读取 `references/humanizer-daily.md` 做最后一遍编辑。它只调整句子、节奏和空话，不能改变榜单排序、数字、产品名或 X 榜单事实。

## 单条测试与素材操作

- 正常日报写 8–12 条。只有用户明确要求单条测试时，才保留榜单第一条作为 `01`；页面仍使用完整日报的标题、导语、编号卡片和页脚结构，读者可见的 Markdown 与 HTML 不出现“测试”字样。
- 图片按**文章实际出现顺序**命名：`01.jpg`、`02.jpg`；同一条的补充图使用 `01-1.jpg`、`01-2.jpg`。每张图仅放在对应新闻卡中一次，第一条图片可作为该卡的封面；不在文章末尾重复追加素材。不要生成 `preview.png`。
- 选定图片后，先阅读 [素材操作说明](references/material-workflow.md)，再运行 `scripts/register-daily-material.mjs` 自动编号、复制到当天 `assets/` 并更新 `materials.json` 与 `assets/materials.md`。先由 Agent 在元数据中写清“对应内容”和“视频使用”，再登记素材。
- 完稿后按素材操作说明运行 `scripts/validate-daily-output.mjs YYYY-MM-DD`。修复它报告的目录结构、链接、素材命名和登记问题后再交付。

## 文章应该怎样写

- 标题由**榜单第一条的变化**加上**当天可看的条目数量**组成，优先具体、口语、有信息差。例如：`OpenAI Sol 降价 20%，今天 AI 圈还有 9 个新变化`。单条测试保留日报语境但不虚构未写入的条目数量。不能使用空泛的“AI 日报｜今日资讯”。
- 标题定稿前，在内部按不同句式拟 3 个候选，选出最具体的一条；不向读者展示候选。公众号标题优先控制在 18–32 个汉字，产品名和核心变化尽量放在前半句；数字必须来自当天材料，不用“多个”“一系列”代替。禁用“震惊、重磅、炸裂”等空泛词，也不用“XX 发布了”作标题。数字清单、教程、对比、亲测等标题公式只适用于材料确实具备相应内容的长文，不能套进日报快讯。
- 开头只用 2–3 句快速报出第一条和当天范围，不写“共同趋势”“行业结论”或强行主题。
- 每条是独立的小新闻卡：编号、短标题、一段 80–160 字的自然叙述。模仿 X 榜单的事件组层次和信息密度：先用榜单导语报出事件，再自然整合主帖详情与关联信源中的范围、机制、条件等事实，写成完整快讯。用自己的中文重新组织，不能逐句复制榜单或原帖；不加入“对谁有用”“为什么值得关注”等主观影响分析，也不要使用这类机械标签。**读者正文不得出现“榜单称／榜单主帖／主帖给出的细节／相关帖／关联帖／事件组”等采编过程语言；它们只用于内部整理，正文直接陈述已确认的新闻事实。**
- 第一条应最完整；只要事件组 `thumb` 直接相关且清晰，就采用为该条封面/配图。其余条目同样逐条使用合格的 `thumb`；普通图和视频封面均可采用。没有 `thumb` 或相关清晰图片时才使用纯文字，不用作者头像或无关图片。`article.md` 与 `wechat.html` 必须在对应新闻位置引用同一张封面／配图；`article.md` 的首图放在标题之后、导语之前。
- 结尾只放精简的“信息整理自 X 榜单赛道榜及相关公开页面”，不强行写总结、观察或建议。正文不展示 X 链接；完整原始链接放在 `sources.json` 供内部存档。
- `wechat.html` 使用 `references/aibyte-signal-green.md` 的 AIBYTE「信号绿」主题。它借鉴“摸鱼绿”的信息层级和公众号兼容做法，但组件和代码必须原创，不能复制其模板。

## 交付与轻量检查

同一日期目录必须有：

1. `article.md`：8–12 条可读日报正文。
2. `wechat.html`：可复制到公众号后台的内联样式 HTML；第一条使用封面。
3. `sources.json`：每条记录榜单链接、X 原帖链接（如有）和补充链接（如有）。无需逐条官网验证。
4. `materials.json`：记录封面和实际采用的素材；没有使用就写明原因。
5. `assets/materials.md`：按素材文件名说明对应新闻内容、文章位置、视频口播使用位置和 `evidence` / `illustration` 类型。

只检查：筛选条件正确、榜单顺序正确、条目数足够（明确单条测试除外）、标题具体、采用的图片相关清晰、Markdown 与 HTML 一致、HTML 没有 X 链接、素材已登记、没有 `preview.png`、没有虚构榜单未提供的事实，并完成 Humanizer 日报检查。不要把日报写成研究报告，也不要生成视频、提交 GitHub 或部署网站。
